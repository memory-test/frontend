# Ясная Память — Frontend

## Getting Started

```bash
npm install
npm run prepare
npm run dev
```

Открой [http://localhost:3000](http://localhost:3000) в браузере.

## Структура проекта

Весь код приложения находится в папке `source/` по методологии FSD:

- `app` — инициализация приложения, провайдеры
- `pages` — композиция страниц
- `widgets` — крупные самостоятельные блоки UI
- `features` — пользовательские сценарии
- `entites` — бизнес-сущности
- `shared` — переиспользуемые утилиты, UI-кит, константы

## Архитектура

В рамках папки `source` (FSD) соблюдаем следующие правила:

- не импортируем ничего с верхних уровней
- не импортируем ничего из соседних модулей (кроме папки `shared`)
- используем алиасы для импорта (`@app`, `@pages`, `@widgets`, `@features`, `@entites`, `@shared`); внутри модуля импорты — относительные
- именуем файлы в кебаб-кейсе (`kebab-case`)
- компоненты описываем стрелочными функциями с явным указанием типа:

```tsx
const RootLayout: React.FC<React.PropsWithChildren> = ({ children }) => {
  ...
};
```

### Структура слоя

- `index.ts` — файл реэкспорта (либо сам компонент, если модуль простой)
- `ui` — папка с реализацией UI
- `config` — папка/файл с конфигами и константами модуля
- `types` — папка/файл с типами
- `hooks` — папка с хуками
- `utils` — папка/файл со вспомогательными функциями
- `forms` — папка/файл с формами и всем, что с ними связано

## Конвенции по коду

- именуем файлы в кебаб-кейсе: `my-component.tsx`
- используем постфиксы, если файлов в папке несколько, либо краткие названия: `my-component.types.ts` / `types.ts`, `my-component.styles.module.css` / `styles.module.css`
- именуем типы и интерфейсы с префиксами: `type TLogoProps`, `interface IUser`
- если структура компонента простая (один файл для стилей, UI, типов и т.п.) — не раскладываем по папкам, всё лежит в одной папке; если файлов одного типа несколько — раскладываем по папкам (`ui`, `styles`, `types`, `utils`, `configs`, `hooks` и т. п.)
- для слайсов (модулей) используем фасады — файлы реэкспорта `index.ts`, которые определяют, что можно использовать извне; глубокие импорты (напрямую из внутренних файлов модуля, минуя `index.ts`) считаются нарушением
- импортируем что-либо из модулей только через алиасы: `@app`, `@pages`, `@widgets`, `@features`, `@entites`, `@shared`

## Работа со ссылками

Для централизованного управления URL используется модуль `source/shared/lib/routes/config.ts`.

Сущности:

- **Сегменты** — из каких статичных кусочков состоят URL
- **Параметры** — из каких динамических кусочков состоят URL
- **Квери-параметры** — допустимые имена query-параметров и их представление в URL
- **Роуты** — собираются из списка сегментов и параметров

### Формирование ссылок

```ts
createUrl(); // /
createUrl(routerPath.profile); // /profile
createUrl(routerPath.profileById, { id: '42' }); // /profile/42
```

### Работа с квери-параметрами

```ts
const { queryParams, setQueryParams } = useRouteQueryParams();

// чтение: string | null
const query = queryParams.query;

// установка параметров
setQueryParams({ query: 'react', pageNumber: null });
```

## Работа в Git

- `main` — стабильная ветка, не трогаем до завершения работы над проектом.
- `develop` — целевая ветка, в ней находится актуальный результат разработки.
- Ветка задачи создаётся от `develop` для реализации конкретной фичи из таск-менеджера.
- В комментариях к задаче в таск-менеджере указываем ссылку на связанный пулреквест.

### Именование веток

`[префикс]/[номер задачи]-[краткое описание]`

Пример: `feat/5-add-radix-ui`

### Префиксы

| Префикс    | Значение                   |
| ---------- | -------------------------- |
| `feat`     | новая фича                 |
| `refactor` | рефакторинг                |
| `fix`      | фикс (`hotfix:` — хотфикс) |
| `release`  | релиз                      |

### Коммиты

`[префикс]: [комментарий]`

Пример: `fix: change route redirect`
